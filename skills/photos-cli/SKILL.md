# photos-cli

`photos` is a Go (Cobra) command-line client for the photos gRPC server, which
stores photos in Google Cloud Storage and their metadata in a database. This
skill explains how to drive the client to browse, transfer and organise
photos. It does **not** cover starting the server (`photos serve` is out of
scope).

## Mode safety: mutating vs read-only commands

Commands that upload, copy, move, delete or update **mutate data**.

- Run them only in an action / edit-capable mode.
- Never run them in a read-only planning mode ("Plan mode", "Ask mode", ...).
  There, restrict yourself to `list`, `get` (GET/HEAD signed URLs only),
  `download` and `download-streaming`.

## Connecting to the server

Every client command needs the service URI, via flag or config:

| Flag             | Purpose                                      |
| ---------------- | -------------------------------------------- |
| `-s, --service`  | `host:port` of the server (required)         |
| `-i, --insecure` | Allow an insecure connection                 |
| `--config`       | Config file (default `$HOME/.photos.yaml`)   |

Resolution order: flag, then environment variable (`PHOTOS_` prefix, e.g.
`PHOTOS_SERVICE`, `PHOTOS_INSECURE`), then `$HOME/.photos.yaml`.

```bash
export PHOTOS_SERVICE=photos.example.ts.net:8080
photos list directories
```

The server is per-user: the caller is identified over Tailscale and every
record is scoped to them. Confirm any command's flags with
`photos <command> --help`.

## Concepts

- **Object ID**: the photo's path in the bucket, e.g. `2024/vacation/a.jpg`.
  It is the identifier every command takes.
- **Directory**: a virtual prefix of object IDs (e.g. `2024/vacation`); it
  exists while it contains photos.
- **Index**: an optional `index.md` per directory describing it. Its content
  must start with YAML frontmatter delimited by `---`.
- **Derived assets**: `.webp`, `_preview.jpg` (DNG previews) and `_thumb.jpg`
  objects generated by the server. They are not photos; do not upload, move
  or delete them directly.

## Read-only commands (safe in any mode)

| Command               | Flags                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| `list directories`    | `-p/--prefix`, `-r/--recursive` (all nested directories)                                                      |
| `list photos`         | `-p/--prefix` (photos in sub-directories are not included), `--page-size`, `--page-token`, `-f/--format text\|json` |
| `get photo`           | `-o/--object-id` (required); `--show-photo` renders via the Kitty graphics protocol, so do not use it        |
| `get index`           | `-p/--prefix` (required), `-o/--output FILE` (stdout otherwise)                                               |
| `get signed-url`      | `-o/--object-id` (required), `-e/--expiration` seconds (default 3600, max 604800), `-m/--method` (default `GET`) |
| `download`            | `-o/--object-id` (required), `-f/--file` (stdout otherwise)                                                   |
| `download-streaming`  | Same as `download`, streamed in chunks; prefer it for large files and videos                                  |

`get photo` prints metadata: filename, content type, size, dimensions, date
taken, camera, exposure, location, video duration, MD5 and derived asset IDs.

`get signed-url --method PUT` or `DELETE` hands out write access to the
object; treat it as a mutating command.

## Mutating commands

| Command                   | Flags                                                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `upload`                  | `-f/--file` (required), `-o/--object-id` (defaults to the filename)                                                       |
| `upload-streaming`        | Same as `upload`, plus `-c/--chunk-size` bytes; prefer it for large files and videos                                      |
| `bulk-upload-streaming`   | `-f/--file` (required, repeatable), `-c/--chunk-size`; object IDs are the filenames; results print as each file finishes |
| `copy photo`              | `--source ID`, `--destination ID` (both required)                                                                         |
| `move photo`              | `--source ID`, `--destination ID` (both required); the source is deleted                                                  |
| `delete`                  | `-o/--object-id` (required)                                                                                               |
| `delete index`            | `-p/--prefix` (required)                                                                                                  |
| `update metadata`         | `-o/--object-id` (required), `-c/--content-type`, `-m/--metadata key=value` (repeatable); at least one of `-c`/`-m`      |
| `update index`            | `-p/--prefix` (required) and exactly one of `-m/--markdown`, `-f/--file`, `-e/--editor` (opens `$EDITOR`; interactive, so agents should use `--file` or `--markdown`) |
| `update database`         | `--update-metadata`, `--update-metadata-pause-in-seconds N`                                                               |
| `update webp`             | `--update-metadata-pause-in-seconds N`                                                                                    |

`update database` syncs the database with the bucket: adds objects missing
from the database, removes rows whose objects are gone (and rows for derived
assets), and with `--update-metadata` downloads every object to re-extract
EXIF, generate DNG previews and missing WebP renditions. `update webp`
generates missing WebP renditions for eligible images (JPEG, PNG, GIF, DNG via
its preview). Both stream one progress line per object and a final summary.

## Rules and gotchas

- `copy photo` and `move photo` fail if the destination already exists, and
  reject a destination equal to the source.
- `update index` creates `index.md` if the directory has none; the content
  must include YAML frontmatter (`---\n---\n` at minimum).
- Text output of `list photos` prints object IDs only, without the next page
  token. Use `--format json` (`{"photos": [...], "next_page_token": "..."}`)
  and pass the token to `--page-token` to paginate.
- `update database --update-metadata` and `update webp` download every
  object, which is slow and expensive; ask before running them. Per-object
  failures are logged and skipped, not fatal.
- `download` without `--file` writes binary data to stdout; always pass
  `--file` unless piping.
- `list`, `get`, `copy`, `move` and `update` alone are parent commands;
  always add the noun. `delete` alone **deletes a photo**; `delete index`
  deletes an index.

## Common workflows

```bash
# Browse
photos list directories --recursive
photos list photos --prefix 2024/vacation --format json
photos get photo --object-id 2024/vacation/a.jpg

# Upload a batch, then check it
photos bulk-upload-streaming -f a.jpg -f b.jpg
photos list photos --prefix ""

# Reorganise
photos move photo --source a.jpg --destination 2024/vacation/a.jpg

# Describe a directory
photos get index --prefix 2024/vacation --output index.md
photos update index --prefix 2024/vacation --file index.md

# Share for a day
photos get signed-url --object-id 2024/vacation/a.jpg --expiration 86400

# Fetch a large video
photos download-streaming --object-id 2024/vacation/clip.mp4 --file clip.mp4
```
